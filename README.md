# まとめてコード署名ツール

個人事業主・中小IT企業向けに、複数のWindowsアプリへまとめてコード署名できるツールです。配布するEXE・DLLにデジタル署名を付け、発行元の確認と改ざん検知を支援します。チェックしたファイルだけを処理し、成功・スキップ・失敗の理由を一覧で確認できます。

Azure Key Vaultの証明書を使う、C# / Windows Forms / .NET 10製のGUIです。接続先・証明書名・各ID・発行元・認証情報の初期値は空欄です。証明書の発行やAzure環境の作成は行いません。

## ダウンロード

[リリース一覧](https://github.com/happyboy20/batch-code-signing-tool/releases)から `DigitalSigningTool.NET10.exe` をダウンロードしてください。EXEは単体ですが、別途.NET 10 Desktop Runtime（x64）が必要です。AzureSignToolは設定画面から自動導入できます。

本ツールは署名対象ファイルへ直接書き込みます。配布前のコピーを用意して利用してください。コード署名によってWindowsの警告が必ずなくなるわけではありません。

## 開発

Visual Studioで `DigitalSigningTool.NET10.sln` を開いてください。プロジェクトを直接開く場合は `DigitalSigningTool.NET10.csproj` です。.NET 10 SDKとWindowsデスクトップ開発環境が必要です。

```text
Source/
  Program.cs          起動・共通デザイン・エラー表示
  MainForm.cs         ファイル一覧・対象選択・署名開始
  SettingsForm.cs     設定画面・自動セットアップ画面
  Settings.cs         設定保存・暗号化・入力検査
  SigningService.cs   署名・Windows API検査・中止・エンジン導入
Images/
  app.ico             アプリアイコン
  app.svg             アイコン画像の元データ
Tests/                回帰テストと非表示の画面検査
```

自作部分はC#の5ファイルに整理しています。スクリプトやアイコン生成プログラムは使いません。署名エンジンにはAzureSignToolを使用します。JSONはC#の標準機能で読み書きする設定データです。

## 利用環境

- Windows x64と.NET 10 Desktop Runtime（x64）。本体EXEにランタイムは同梱していません。
- 利用者側で用意したAzure Key Vaultの証明書・秘密鍵、必要なアクセス権、認証情報。
- Azureおよび設定したRFC 3161タイムスタンプサーバーへの接続。
- AzureSignToolは設定画面の「自動セットアップ」から導入できます。

## 使い方

1. `DigitalSigningTool.NET10.exe` を起動します。初回はメイン画面を表示します。
2. 「設定」でKey Vault URL、証明書名、クライアントID、テナントID、シークレット、証明書のCN、タイムスタンプURLを設定します。
3. AzureSignToolがなければ「自動セットアップ」で「自動インストール」を押します。
4. 「ファイルを追加」で複数ファイルを選択するか、「フォルダーを追加」で配下のEXE・DLLを一覧に追加します。
5. チェックした行だけを処理します。「全選択」「全選択取消」「一覧をクリア」も使用できます。重複するパスは追加しません。
6. 「チェックしたファイルを署名」で開始します。結果は○成功・△スキップ／中止・×失敗とし、理由を詳細列に表示します。
7. 最後の場所列をクリックすると保存先フォルダーが開きます。「中止（強制停止）」または画面の×で後続処理を中止できます。

他社の署名は上書きしません。発行元が判別できない既存署名も変更しません。署名は元ファイルへ直接反映し、バックアップや自動復元は行いません。署名開始後の失敗・中止ではファイルが変更されている可能性があるため、一覧の理由を確認してください。結果ログは保存しません。

## 設定と利用期間

設定は `%LOCALAPPDATA%\DigitalSigningTool.NET10\settings.json`、自動導入したエンジンは同フォルダーの `tools` 配下へ保存します。他の版の設定・認証情報は自動で読み込まず、コピーや移行もしません。

利用期間の制限は初期状態で無効です。必要な場合だけ「利用期間の制限を有効にする」をチェックします。期間の入力欄は、そのPCの日付から1年間を初期表示します。終了日当日は利用でき、開始日前のPC日付でも警告しません。制限を有効にして終了日を過ぎた場合は設定画面へ移動し、更新するまで署名できません。保存せず閉じることもできます。

「次期へ更新」は利用期間を1年進めます。証明書名が半角4桁の年で始まる場合だけ、その年も進めます。年で始まらない証明書名は変更しません。Azure側の証明書の発行・登録は別途必要です。各項目は直接編集し、「保存」で確定します。

シークレットはWindows DPAPIでユーザー単位に暗号化します。別ユーザー・別PCでは再入力してください。保存設定が壊れている場合は初期値へ戻して続行せず、原因を表示して終了します。エンジンへの認証情報の受渡しには現在コマンド引数を使用するため、同ユーザーや管理者による引数の参照が可能な点は残ります。

## 署名検査とセットアップ

署名検査はC#からWindows標準APIの [WinVerifyTrust](https://learn.microsoft.com/windows/win32/api/wintrust/nf-wintrust-winverifytrust) を呼び出し、未署名・改ざん・信頼エラーを区別します。証明書の取得や失効照会はオンラインで行わず、キャッシュを使用します。タイムスタンプの存在も確認します。カタログ署名のあるファイルや、署名者を取得できない埋込み署名も上書きから保護します。

自動セットアップは [AzureSignTool v7.0.1](https://github.com/vcsjones/AzureSignTool/releases/tag/v7.0.1) のWindows x64単体EXEをダウンロードし、公開サイズとSHA-256を照合してから配置します。通常は管理者権限不要です。利用者の中止と全工程5分の制限時間に対応します。

## ビルド・検証

```text
dotnet build DigitalSigningTool.NET10.sln -c Release
dotnet publish DigitalSigningTool.NET10.csproj -c Release -o 配布用
dotnet run --project Tests/DigitalSigningTool.Checks.csproj -c Release
dotnet run --project Tests/UI/DigitalSigningTool.UiChecks.csproj -c Release
```

配布物はランタイム非同梱の単一EXEです。テストは製品プロジェクトを参照し、一時フォルダーのデータ、Windows APIによる読取検査、C#製の検証用プロセスを使用します。実署名、Azure接続、ダウンロード、利用者の実設定への書込みは行いません。実際のAzure署名による試験は別途必要です。
